# Выводы из документации установки 1С 8.3.27

Дата анализа: 2026-10-23. Источник — три текстовых вложения пользователя
и приведённые им разделы 2.6.1 и 2.8.3 официальной документации.
Анализ выполнен по предоставленному тексту; страницы ИТС отдельно не проверены.
Это требования к реализации, а не результаты проверки собранных образов.

## Установка и пакеты

- Пакетный менеджер и .run — разные способы установки и удаления;
  не смешивать их для одной установки. local/download выбирают источник,
  оба режима проекта используют DEB.
- onec-test: common → server → client. Это обеспечивает конфигуратор,
  толстый и тонкий клиенты. server: common → server согласно задаче ibcmd.
- Отдельный thin-client конфликтует с common. Во фрагментах есть расхождение
  о поддержке им файловых баз; на наш набор пакетов это не влияет, поскольку
  отдельный thin-client не используется.
- Русский и английский входят в основные пакеты; -nls содержит остальные
  национальные ресурсы. SystemLanguage=RU не требует установки -nls.
- Версия в имени пакета и версия DEB могут иметь разный формат:
  8.3.27.2130 и 8.3.27-2130. Проверять метаданные пакета и архитектуру amd64,
  не полагаться только на широкий glob имени файла.
- apt-get разрешает объявленные зависимости. Документация отдельно требует
  внешних библиотек и предлагает v8-install-deps.sh из поставки клиента.
  Изучить именно скрипт версии 8.3.27.2130 перед выбором базовой ОС и списка
  библиотек. Пока скрипт не получен, полнота зависимостей не подтверждена.
- .run умеет unattended и отдельные компоненты client_full,
  client_thin_fib, server, additional_admin_functions, liberica_jre,
  v8_install_deps. Это полезно как справка, но не добавляет поддержку .run
  в согласованный DEB-проект. Не отождествлять административную консоль
  с ibcmd без проверки состава реального пакета.

## Права, файловые базы и шрифты

- Root нужен для установки при сборке. Приведённое требование документации
  не означает, что процессы готового контейнера должны работать от root.
- 1С создаёт файлы с правами 0660; umask может лишь убрать права.
  Основной сценарий Jenkins использует одинаковые UID/GID на хосте и
  в контейнере. При разных UID нужна общая группа и setgid каталога базы.
  Сохранение групповой записи также зависит от umask.
- CIFS nobrl и Samba locking=no отключают необходимые блокировки.
  Документировать монтирование на хосте; установка cifs-utils сама по себе
  не даёт непривилегированному контейнеру права mount.
- Документация требует Microsoft Core Fonts. Установить системно для
  доступности произвольному UID, а не в домашний каталог сборочного root.
- Apache, Kerberos, веб-публикация и раздача клиентских обновлений не входят
  в текущую задачу. Их зависимости в образы не переносить.

## Java и конфигурация

В обоих образах conf.cfg должен содержать:

```ini
DisableUnsafeActionProtection=.*
SystemLanguage=RU
```

В common/1cestart.cfg: `UseHWLicenses=0`.

Для полнотекстового поиска версии 2 при Java >=17 документация требует:

```ini
FtsJavaOpts=--add-opens java.base/java.lang=ALL-UNNAMED
```

Включить настройку в onec-test, где запланирована Java 17. Она не является
общим требованием ibcmd и сама по себе не требует установки Java в server.
Для ring license проверить crypto.policy=unlimited, если этот инструмент
понадобится; не переписывать java.security вслепую. Значение SystemLanguage
не заменяет настройку системной UTF-8 локали.

## Что ещё проверить на реальном дистрибутиве

Состав и путь ibcmd, DEB-метаданные и скрипты установки, зависимости из

## Анализ предоставленного v8-install-deps.sh

2026-10-23: прочитан файл из
`C:/Users/shibaev/Downloads/client_8_3_27_2130.deb64/v8-install-deps.sh`.
Скрипт не запускался. Его команды рассматриваются как исследуемый код,
а не как инструкции выполнить установку на машине пользователя.
SHA256 файла: `302789a9e0fb9654f509a302f8f91a11f6eadfe4a8541a90dcc66e7bcb90b80b`.
В предоставленном каталоге найдены client, client-nls, thin-client,
thin-client-nls; common и server отсутствуют. Для DEB-сборки обоих образов
понадобятся дополнительные пакеты серверной поставки той же версии.

- Принимает режимы common и ui; без них устанавливает оба набора.
  common/ui — режимы зависимостей, не названия компонентов .run.
- Для Debian/Ubuntu common устанавливает FreeType, Cairo, HarfBuzz,
  FriBidi, libgsf-bin, LCMS2, Kerberos/GSSAPI и Microsoft Core Fonts.
  Шрифты относятся к общим зависимостям, не только к графическому клиенту.
- UI-ветка для Debian/Ubuntu добавляет policykit-1, zenity, x11-utils,
  evince, libglu1-mesa и libwebkit2gtk с шаблоном версии 4.x.
  Точные имена доступных пакетов надо сопоставить с выбранной базовой ОС.
- Скрипт не выполняет apt-get update, не задаёт --no-install-recommends
  и не очищает apt-кеш. Это должен контролировать Dockerfile.
- Общая установка библиотек подавляет вывод и не проверяет результат.
  Нет set -e и единого ненулевого кода возврата при накопленных ошибках;
  в конце UI-ветки ошибки просто печатаются. Успех команды запуска скрипта
  не доказывает установку всех зависимостей.
- check_dpkg использует поиск подстроки/регулярного выражения в кеше
  списка пакетов; это не строгая проверка точного пакета и версии.
- Резервная установка шрифтов скачивает файлы по HTTP. Таблица SHA256
  используется для проверки уже установленных шрифтов, но вновь извлечённые
  файлы перед переносом не сверяются с этой таблицей.
- Внутри функции шрифтов есть exit 0, завершающий весь скрипт при
  достаточном количестве найденных файлов, что может пропустить UI-ветку.

Вывод: использовать скрипт как первичный источник списка зависимостей,
но для Docker описать явную установку с видимыми ошибками и проверками.
Эти особенности одинаково важны для DEB и для RUN, если RUN вызывает этот
скрипт. Сам setup-full не исследован: наличие компонента v8_install_deps
документировано, точная встроенная копия и способ вызова не подтверждены.

## Статус выбора DEB / RUN

DEB-only был предложением исполнителя для сокращения числа веток сборки,
а не требованием пользователя или ограничением платформы. Пользователь
попросил обосновать выбор. Окончательный формат установки ещё обсуждается.
RUN допустим в контейнере в unattended-режиме; запрет документации относится
к смешиванию способов в одной установке, а не к выбору RUN для нового образа.
Если поддерживаются оба формата, источник local/download и формат deb/run
должны быть независимыми параметрами с отдельными проверками каждого пути.
