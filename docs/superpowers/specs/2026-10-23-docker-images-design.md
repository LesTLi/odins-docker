# Образы 1С для Jenkins и ibcmd

## Цель

Создать самостоятельный проект odins-docker, заменяющий используемую цепочку
сборки из LesTLi/onec-docker. Приоритет — понятное сопровождение, два конечных
образа и работа без root. Целевая версия платформы: 8.3.27.2130, Linux amd64.

## Образы и структура

- `onec-test/Dockerfile`: полный клиент 1С, OneScript, пакеты add и
  vanessa-runner, Java 17, Xvfb, VNC и утилиты тестирования, включая scrot
  и совместимую обёртку nircmd для снимков экрана, pandoc, сетевые утилиты.
- `server/Dockerfile`: пакеты платформы common и server с зависимостями.
  Назначение — выполнение ibcmd. Кластер 1С и ragent автоматически не запускаются.
- `scripts/`: общие операции получения и установки платформы, сборка и
  небольшие сценарии запуска и проверки.
- `distr/`: локальные дистрибутивы, исключённые из Git.
- `examples/`: использование в Jenkins и команды запуска.

Не создавать дополнительные публикуемые базовые образы. Внутренние стадии
Dockerfile допустимы для загрузки и подготовки дистрибутивов. PostgreSQL,
EDT, сервер хранилища конфигураций и Jenkins agent в состав не входят.

## Получение платформы

Единая команда сборки принимает образ, версию и `DIST_SOURCE`:

- `local` (по умолчанию): использует дистрибутив из `distr/` для заданной
  версии. Отсутствие файлов или несовпадение версии завершает сборку ошибкой.
- `download`: получает дистрибутив заданной версии с портала 1С на отдельной
  стадии. Учётные данные передаются через BuildKit secrets. Секреты нельзя
  передавать через ARG/ENV, печатать в лог или сохранять в итоговом образе.

Для server в DEB-режиме устанавливаются common и server; для onec-test
добавляются пакеты полного клиента. Установка локальных deb выполняется через
apt-get с разрешением объявленных пакетных зависимостей. Этого может быть
недостаточно для внешних библиотек платформы: изучить v8-install-deps.sh
из поставки 8.3.27.2130 и проверить фактические зависимости исполняемых файлов.
Выбор пакетов должен быть явным, без
случайного захвата иной версии или архитектуры. Формат архива с портала и
поддерживаемый способ его получения проверяются при реализации.

Оба источника приводят к одному набору входных файлов выбранного формата. Источник
дистрибутива не является способом установки: local/download не означают
DEB/RUN. Не смешивать установку пакетным менеджером и .run в одном образе;
Подтверждён план с INSTALL_FORMAT=deb|run, независимо от local/download.
RUN использует unattended и явный выбор компонентов; оба формата проверяются
отдельно. Для onec-test в DEB-режиме нужны common, server,
client; отдельный thin-client конфликтует с common и не устанавливается.
Русские и английские ресурсы входят в основные пакеты, -nls для них не нужны.
Не переходить
молча с local на download. Не включать установочные архивы, загрузчик и его
кеш в итоговый образ. Не публиковать образы автоматически после сборки.

## Права и запуск

В обоих образах задан непривилегированный пользователь по умолчанию.
Также поддерживается `docker run --user UID:GID`, где UID/GID принадлежат
пользователю Jenkins на агенте. Для корректной работы приложений обеспечить
определение пользователя и доступный домашний каталог даже для UID,
отсутствующего в /etc/passwd; конкретный механизм проверить при реализации.

Программы и библиотеки устанавливаются в системные каталоги с правом чтения
и исполнения для обычного пользователя. OneScript и его пакеты не должны
зависеть от /root. Установка пакетов выполняется при сборке, не при старте.
Пользовательские настройки, временные файлы и кеши записываются в доступные
каталоги. Смонтированный workspace должен быть доступен переданному UID/GID.
Не применять рекурсивный chmod 777 или chown к workspace и не требовать root
для исправления прав при запуске.

ibcmd, клиент 1С и тестовые инструменты доступны через PATH. Произвольная
команда контейнера сохраняет свои аргументы и код завершения. Обработка
сигналов и завершение вспомогательных процессов должны быть корректными.
Для onec-test предусмотреть виртуальный экран для тестов, а VNC — включаемым
режимом диагностики с документированным безопасным способом подключения.

## Настройки 1С

Оба образа содержат:

```ini
# /opt/1cv8/conf/conf.cfg
DisableUnsafeActionProtection=.*
SystemLanguage=RU
```

```ini
# /opt/1cv8/common/1cestart.cfg
UseHWLicenses=0
```

Звёздочка здесь записывается без обратной косой черты. При установке сохранить
прочие настройки производителя и исключить дубли ключей. Проверить связь
версионного каталога платформы с общей конфигурацией. Документация объясняет,
что отключение защиты небезопасных действий запрошено для тестового окружения.

Для onec-test с Java 17 добавить в conf.cfg параметр для полнотекстового
поиска версии 2: `FtsJavaOpts=--add-opens java.base/java.lang=ALL-UNNAMED`.
Это требование указанного компонента, а не всех запусков платформы.
Java и ring license не добавляются в server только на основании этого
пункта документации. Если потребуется ring license, проверить фактическое
crypto.policy=unlimited выбранной Java, прежде чем менять java.security.

## Сборка и сопровождение

Базовую ОС выбрать по зависимостям платформы 8.3.27.2130; не смешивать
репозитории разных выпусков Debian/Ubuntu ради старых библиотек. Закрепить
версии сторонних инструментов и проверять контрольные суммы скачиваемых
артефактов там, где они доступны. Предоставленный v8-install-deps.sh
исследован без запуска: использовать его списки common/ui как основу,
но не полагаться на код возврата как доказательство успешной установки.
Подробности — в docs/installation-notes.md. Не использовать плавающий stable/latest
для OneScript и не выполнять бесконтрольный opm update --all.

Учесть требование документации к Microsoft Core Fonts: шрифты должны быть
установлены системно, доступны обоим образам и произвольному UID. При
реализации проверить способ получения и условия установки выбранного пакета.
Root требуется на стадии установки; это не требование запуска контейнера.
Предотвращать запуск служб из установочных скриптов DEB-пакетов при сборке.

Для файловых баз учитывать явно задаваемые платформой права 0660: umask
не расширяет их. При совместной работе разных UID использовать общую группу
и setgid на каталоге базы, подготовленном владельцем на хосте. Не менять
автоматически права смонтированных каталогов. Если используется CIFS/Samba,
не отключать блокировки через nobrl или locking=no; сетевые ресурсы
монтировать на хосте, без привилегированного контейнера.

Добавить .dockerignore, .gitignore и LF для shell-скриптов. Устанавливать
пакеты без рекомендуемых зависимостей там, где это не нарушает работу;
очищать apt-кеш в том же слое. Сборка должна прерываться при ошибках, а
скрипты — корректно обрабатывать пробелы в путях и отсутствующие параметры.
Не выполнять docker system prune и не передавать пароль registry в CLI.

README на русском описывает входные дистрибутивы, оба режима сборки,
настройки версий, запуск ibcmd, Jenkins Pipeline с UID/GID агента,
графический режим и диагностику прав. Лицензии и дистрибутивы 1С пользователь
предоставляет самостоятельно; секреты и лицензии в Git не попадают.

## Проверки и критерии приёмки

### GitHub Actions — основная среда сборки и проверки

По требованию пользователя сборка и интеграционные проверки выполняются
на GitHub-hosted Linux amd64 runner, не на локальном компьютере с сетевыми
ограничениями. Репозиторий LesTLi/odins-docker проверен: private, ветка main.

- `.github/workflows/check.yml`: push и pull_request, проверки shell,
  Dockerfile и workflow без секретов портала 1С.
- `.github/workflows/build.yml`: ручной workflow_dispatch и push в main;
  сборка обоих образов, затем запуск smoke-тестов на том же runner.
  Параметры ручного запуска: версия платформы и выбранный формат установки.
  Форматы DEB/RUN согласованы; матрица должна включать каждый реализованный
  формат и оба образа, чтобы не заявлять поддержку непроверенного варианта.
- Источник в CI по умолчанию download. Secrets ONEC_USERNAME и ONEC_PASSWORD
  передаются загрузчику через BuildKit secrets. При отсутствии обязательных
  секретов завершать сборку с понятной ошибкой, не выдавать пропуск за успех.
- Локальные файлы C:/Users/... недоступны GitHub runner. Режим local означает
  distr/ на машине сборки; для проверки этого режима в Actions скачать
  дистрибутив на runner и передать как локальный вход отдельной сборке.
  Архивы 1С не добавлять в Git и не выгружать как общедоступные артефакты.
- Проверки: точные настройки, версии и запуск ibcmd/OneScript/Vanessa Runner,
  запуск без root с обычным и произвольным UID/GID, запись в bind-mounted
  workspace с проверкой владельца на runner, Xvfb/снимок экрана для onec-test,
  завершение процессов и сохранение кода возврата команды.
- Не выполнять код pull request с секретами через pull_request_target.
  Минимальные permissions contents:read, закреплённые SHA используемых
  actions, timeout и ограничение параллельных повторных запусков.
- Публикация в registry пока не входит в этот этап: сначала сборка и тесты.
  Место хранения готовых образов для Jenkins ещё не выбрано.
- Отчёт содержит ссылку на запуск Actions и результат каждого образа.
  Настоящие тесты конфигурации требуют самой конфигурации и лицензирования;
  smoke-тесты их не заменяют.

Не устанавливать локально Docker-зависимости ради обхода сетевых ограничений.
Локально допустимы редактирование и проверки, не требующие скачивания.

1. Статические проверки Dockerfile и shell-скриптов.
2. Сборка обоих образов из локального дистрибутива 8.3.27.2130.
3. Проверка download с действующими учётными данными при их доступности;
   без них явно указать, что интеграционная проверка не выполнена.
4. Запуск ibcmd и основных инструментов onec-test без root, как с UID
   по умолчанию, так и с другим UID/GID, отсутствующим в образе.
5. Запись в смонтированный workspace: владельцем результата остаётся UID
   агента Jenkins. Проверка HOME, кешей, OneScript и Vanessa Runner.
6. Проверка точного содержимого обоих конфигурационных файлов и отсутствия
   отсутствующих динамических библиотек у исполняемых файлов платформы.
7. Проверка запуска Xvfb, снимка экрана и остановки контейнера.
8. Реальное выполнение тестов конфигурации требует самой конфигурации и
   подходящего лицензирования; не подменять его проверкой наличия бинарников.

На момент исследования Docker CLI установлен, но Docker daemon недоступен.
Дистрибутив и учётные данные ещё не предоставлены. Эти ограничения не мешают
реализации проекта, но должны быть отражены в отчёте о фактически выполненных
проверках; успешную сборку без её выполнения утверждать нельзя.
