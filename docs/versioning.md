# Версионирование и TAR-артефакты

Подтверждено владельцем 2026-10-26. Реализовано и проверено в
[Actions 40265588178](https://github.com/LesTLi/odins-docker/actions/runs/40265588178).
Все восемь сборок/smoke и четыре save/load/upload успешны.
odins-ci:onec-test-run остаётся временным тегом runner;
экспортируемому образу после тестов назначается уникальный тег сборки.

## Три независимые величины

- Версия проекта IMAGE_VERSION: SemVer рецепта, инструментов и интерфейса
  контейнера; например 1.0.0. Одна версия проекта для обоих образов.
- ONEC_VERSION: версия платформы, например 8.3.27.2130.
- Сборка: GITHUB_RUN_ID + GITHUB_RUN_ATTEMPT. Повтор одного коммита
  может получить другие пакеты ОС, поэтому одного Git SHA недостаточно.

Пример тега выпуска: odins-onec-test:1.0.0-1c8.3.27.2130-run.
Пример точной сборки:
odins-onec-test:1.0.0-1c8.3.27.2130-run-b40258325298-a1.
Это составной Docker-тег; собственно SemVer — только IMAGE_VERSION.

Тег выпуска назначается проверенной сборке из Git-тега v1.0.0;
выпущенные теги по правилам проекта не перезаписываются. Ветки разработки
получают только теги конкретной сборки. Теги Docker технически изменяемы.
Новый выпуск продвигает уже проверенный образ, без повторной сборки.
При наличии registry Jenkins должен фиксировать manifest digest.
IMAGE_VERSION берётся из versions.env; первый выпуск — 1.0.0. Поддерживаются
стабильные X.Y.Z без начальных нулей. Git-тег должен быть точно vX.Y.Z
с той же версией, иначе сборка завершится ошибкой. Короткий тег выпуска
добавляется только при push Git-тега в первой попытке. Ручной запуск и
rerun сохраняют только уникальный тег сборки и не заменяют релизный alias.
Для нового выпуска измените IMAGE_VERSION и создайте новый Git-тег;
выпущенные Git-теги не переносите на другой коммит.

SemVer: исправления/совместимые обновления безопасности — PATCH;
новые совместимые возможности — MINOR; несовместимые изменения CLI,
entrypoint, UID/HOME или инструментов — MAJOR. Совместимость инструментов
нужно оценивать по фактическим изменениям, а не номеру зависимости.

## Скачивание без registry

Имя TAR повторяет точный тег сборки, с дополнительным linux-amd64.
Рядом сохраняются SHA256 архива и metadata JSON: тег, версии проекта/1С,
формат установки, архитектура, полный Git SHA, run ID/attempt, image ID.
SHA256 TAR проверяет файл архива, а не manifest digest registry.
В каждом из четырёх artifacts находятся TAR, .tar.sha256 и .metadata.json.
Артефакты доступны после успешного задания; retention — 1 день.
Экспорт не публикует Docker registry или GitHub Release. Поскольку в TAR
содержится 1С, доступ к артефактам определяется доступом к private repository.
local/download — источники одной поставки, не отдельные пользовательские
версии; сведения об источнике можно сохранить в метаданных.
После проверок обеих веток экспортируется один итоговый образ на сочетание
image/format; уникальный тег назначается именно ему. Если потребуется
экспортировать обе ветки, их идентификаторы сборок должны различаться.

В образе: org.opencontainers.image.version (IMAGE_VERSION), revision
(полный Git SHA), source, created. Версия 1С и формат — собственные labels,
например io.github.lestli.odins-docker.onec.version и install.format.
В текущей реализации полный ключ формата:
io.github.lestli.odins-docker.install.format.
