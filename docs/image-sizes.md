# Размеры DEB и RUN

Измеряются в GitHub Actions скриптом scripts/image-size-report.sh.
size-report.txt сохраняется рядом с TAR, SHA256 и JSON. Размер image из
docker image inspect, размер TAR и размер ZIP artifact — разные величины.
Все числа GB ниже десятичные, не GiB.

## Подтверждённые наблюдения 2026-10-26

Запуск: https://github.com/LesTLi/odins-docker/actions/runs/40284384293.

Для server: DEB image 1 720 083 363 байта, RUN image 1 422 386 838 байт.
Все 196 системных DEB-пакетов совпадают по именам, версиям и Installed-Size;
в DEB-варианте дополнительно зарегистрированы два пакета платформы 1С.
Каталог /opt/1cv8 занимает 1 463 392 KiB против 1 173 436 KiB в RUN.
DEB содержит дополнительные установщики клиентского агента в ExtDst:
87 260 070 + 61 317 217 + 61 008 381 + 24 464 215 байт (около 234 MB).
Также DEB содержит devdocs_ru.bin/devdocs_root.bin и другие отличия состава.
Это объясняет большую часть разницы; полный побайтовый diff не выполнялся.

Для onec-test: DEB image 3 887 381 636 байт, RUN image 4 038 293 511 байт.
RUN больше примерно на 151 MB. В RUN дополнительно присутствует
ExtDst/1c-enterprise-client-application-agent-1.0.14.5.e2k.sh размером
134 421 456 байт; в топ-30 DEB его нет (там порог меньше 19 MB).
Это объясняет основную часть разницы клиента. /opt/1cv8 занимает
2 775 284 KiB в RUN и 2 626 828 KiB в DEB. Разница не означает, что
RUN всегда компактнее: результат зависит от компонентов и состава поставки.

DEB устанавливает целые common/server/client, RUN выбирает компоненты
установщика. Одинаковая версия платформы и проверка нужных CLI не означают
одинаковый набор всех поставляемых файлов. Нельзя объяснять разницу только
сжатием исходных установщиков: они не сохраняются в конечном образе.

Оптимизация удалением файлов поставщика в этом изменении не выполнялась.
До выбора основного формата релиза варианты имеют отдельные deb/run теги.
